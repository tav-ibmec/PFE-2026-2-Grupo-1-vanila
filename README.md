# AC Vanilla — PKZ Lab & Studio One to One

Documentação e código da Avaliação Continuada (AC) do Projeto Front-End do IBMEC, desenvolvidos pelo Grupo 1, turma de sexta-feira. O projeto consiste na criação de um hub institucional e de páginas para duas empresas do segmento de treinamento físico: PKZ Lab e Studio One to One.

## Sobre o trabalho

O projeto propõe uma solução institucional que conecta as duas empresas por meio de um hub central, permitindo que os usuários acessem as informações específicas de cada marca. O objetivo é ampliar a divulgação das empresas e facilitar o acesso do público a serviços profissionais de treinamento físico.

O desenvolvimento foi realizado ao longo do semestre, com versionamento de código pelo Git e GitHub e preparação para publicação por meio do GitHub Pages.

- **Proposta do site:** página inicial (hub) para escolha entre as empresas e uma landing page para cada marca, com apresentação, diferenciais, planos, avaliações, formulário de aula experimental, FAQ e contato por WhatsApp.
- **Tecnologias:** HTML5 semântico, CSS3 e JavaScript ES6, sem frameworks externos.
- **Identidade visual:** proposta profissional e minimalista, com padronização de cores, tipografia, componentes e estilos.
- **Público-alvo:** adultos, crianças, jovens atletas e seus responsáveis, conforme os serviços de cada empresa.
- **Entrega:** consolidação do código-fonte e da documentação do projeto, com integração das páginas e preparação para os testes e a publicação.

## As empresas

### PKZ Lab (Playmakerz)

Laboratório de performance e avaliação física voltado à formação de jovens atletas. A proposta integra ciência, tecnologia e performance esportiva, com foco no desenvolvimento esportivo desde as primeiras etapas da formação e na orientação de atletas e responsáveis.

### Studio One to One

Espaço de atendimento integrado que reúne treinamento personalizado, fisioterapia e nutrição. A proposta prioriza o acompanhamento individualizado, a saúde, a reabilitação e o desenvolvimento das necessidades específicas de cada aluno.

## Organização do trabalho (Scrum)

A equipe organizou o desenvolvimento em seis sprints, com acompanhamento das atividades por meio de registros de Scrum e versionamento frequente no GitHub. A adoção de commits menores teve como objetivo facilitar o acompanhamento das alterações, a integração do trabalho e a identificação de problemas.

- **Sprints 1 e 2:** estruturação inicial dos arquivos HTML, organização dos modais e adoção de commits menores.
- **Sprints 3 e 4:** desenvolvimento paralelo do CSS, estruturação do agendamento e divisão das tarefas de implementação visual.
- **Sprint 5:** integração do JavaScript, consolidação das variáveis CSS e padronização da documentação.
- **Sprint 6:** testes integrados, garantia da qualidade (QA), correção de problemas visuais e preparação para a publicação no GitHub Pages.

Os registros e documentos de acompanhamento estão organizados na pasta `scrum 2/`.
